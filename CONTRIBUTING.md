# Contributing to MedCue

Thank you for helping improve MedCue. Before proposing a change, read:

1. [Product requirements](docs/PRD.md)
2. [Architecture](docs/ARCHITECTURE.md)
3. [Development workflow](docs/DEVELOPMENT_WORKFLOW.md)
4. [Test strategy](docs/TEST_STRATEGY.md)
5. [Security and privacy](docs/SECURITY_AND_PRIVACY.md)

Use an Issue for a requirement, defect, or technical-debt record. Use a focused
branch and pull request for implementation. Keep examples synthetic and never
include medication records, health data, credentials, device identifiers, or
private signing material.

Pull requests should state the problem, intended outcome, scope, acceptance
criteria, exact commands and results, risk review, and residual follow-up. If a
physical-device or Apple Developer account check is required, record it as
complete or pending rather than inferring it from a simulator build.
