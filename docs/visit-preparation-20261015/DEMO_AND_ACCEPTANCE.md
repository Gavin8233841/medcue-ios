# 演示叙事与验收清单

## 一条连续的故事

主角是一名长期用药的iPhone用户。先说明日常怎么用，再展示积累如何帮助复诊，不从一堆已有数据突然跳到AI结果。演示案例需在开头或资料说明中清楚标注一次；不必每屏反复写“模拟”，但不能让观众误认真实患者或临床研究。

建议故事顺序：录入与确认 → 平常的提醒和轻量记录 → 接入经授权的身体数据 → 准备复诊 → 核对来源与自主分享。

## 约五分钟讲演雏形

以下是待试讲调整的稿件框架。功能描述必须以最终演示版验收为准；未实现部分不能按完成口吻照读。

### 开场与人群 约40秒

“长期用药需要记住的，往往不只是一个吃药时间。还包括自己现在用什么、过去怎么记录、最近身体有什么变化。到了复诊时，这些信息又需要重新整理。我们做MedCue，希望把日常管理和这一次整理连接起来。”

交代目标人群与项目边界。不要声称用户普遍痛苦或引用没有实际做过的访谈；如果来自团队个人经历，只有事实成立且本人愿意时才使用。

### 日常使用 约50秒

展示添加一种演示药品、确认计划、查看当天任务。已有导入或本机识别功能只有真实验证后才演示；识别结果仍由用户确认。不要把聊天图片的本机OCR误说成完整的自动处方识别。

讲述重点是减少日常操作，而非逐一介绍按钮。提醒和记录是基础，不能展示为物理验证吞服。适老模式只展示最关键的一步，避免把答辩变成设置页游览。

### 身体数据成为背景 约40秒

展示HealthKit可读取的健康回顾，说明日期范围、样本覆盖和来源。数据不足时能看出来。明确本次演示数据来源，不暗示所有用户都有手表、所有指标都能取得。

转场句：“这些信息每天都在积累，但如果仍然需要自己把它们翻出来、拼成一份资料，管理的最后一步还是很麻烦。”

### 核心高光 约90秒

点“准备复诊资料”，或输入：“我下周复诊，帮我准备最近30天值得跟医生说的情况。”

依次展示可见范围、实际查询与整理状态、少量清楚的事实和待问问题。点开一条内容，显示对应来源。删除一项不想分享的内容，生成预览。让观众看到用户完成了一件事，而不是看模型输出一大段话。

讲述句：“数字来自我们的记录与确定性统计；AI帮助组织表达。它不替用户作治疗决定，也不会把没有记录解释成没有吃药。”

如网络失败，直接展示真实错误与本机资料仍可用的状态，不偷偷切换到预写答案冒充实时生成。备用录屏必须标明它是预先录制的准确版本演示。

### 技术与差异 约40秒

用一张简单图解释：本机用药记录与授权HealthKit事实 → 同一份任务快照 → 受事实约束的草稿 → 用户选择 → 原生PDF。

强调解决具体任务的集成体验，以及如何核对输出。不以“全球第一”“国内没有”立论，不把使用大模型或Apple API本身当作唯一创新。

### 验证与结尾 约40秒

展示实际完成的证据：准确版本的聚焦测试、真实操作与已获得的反馈。若只有合成案例，明确它验证的是功能和流程，不是疗效。可以说明还有哪些部分尚待真实场景验证。

结尾句备选：“我们希望用药管理留下的信息，最终能够真正为使用者所用：日常更省心，需要回顾时更清楚。”

## 评委可能追问什么

**Apple健康已经做了，为什么还需要你们？**

我们依赖并补充Apple健康，不声称取代它。我们聚焦用药者从日常管理到复诊准备的一个任务，减少跨页面整理，并把资料选择与来源核对放在同一流程。是否真的更方便，需要展示任务对照和实际反馈，不能只凭定位名称回答。

**和通用AI上传截图有什么不同？**

目标是不用用户手工收集截图，直接在授权范围内读取同一时间窗、带来源的结构化事实，并让确认后的资料直接进入预览与导出。若最终实现仍要用户大量复制粘贴，就应承认这项优势没有达成。

**为什么称智能体？**

它处理的是一个有明确输入、步骤和交付物的任务。它能取得本次允许的资料、生成可核对草稿并准备导出；用户始终保留选择与分享决定。若最终只是一个聊天回答，宜称AI助手，而不夸大成已实现任务型智能体。

**AI判断错了怎么办？**

事实数字不交给模型计算；输出引用本次资料，待问问题与事实分开；无来源内容不能进入正式事实区。我们不会承诺绝对正确，也不会自动改药。演示版要展示一个缺数据或网络失败的真实处理。

**有没有真实患者和医生背书？**

按实际证据回答。专业人员审阅建议、志愿者可用性测试和临床研究是三种不同证据。没有的就不写；个人意见也不等于医院认证。

## 最低验收矩阵

|用例|必须看到的结果|证据类型|
|---|---|---|
|正常合成案例|同一范围事实进入草稿及PDF，数值、单位、时间和来源一致|自动断言＋原生操作|
|未记录任务|不变成“确定漏服”或依从性诊断|事实语义断言|
|健康数据为空/稀疏|缺失明确，不补零、不生成确定健康结论|固定夹具＋界面|
|重复来源/单位/时区边界|采用既有明确规则，不能悄悄重复计算|Core聚焦测试|
|用户删选|只影响本次草稿，底层药品/记录不变；PDF跟随选择|快照断言＋原生预览|
|换范围/改记录/刷新|旧草稿需刷新；晚回包不覆盖新资料|状态机测试|
|撤回再授予/许可过期/接收方改变|旧草稿与旧响应不恢复有效，不自动重发或换服务商|状态与网络mock断言|
|重复点击/取消|没有重复请求、重复导出或意外写入|mock调用计数＋UI|
|在线健康摘要|候选真实模型用无隐私合成资料完成至少一次；接收服务和准确版本可说明|真实联调，不以mock代替|
|网络/模型失败|有具体错误，可继续本机资料任务；不伪称AI已生成|故障注入＋界面|
|大字体及返回|重要按钮可达，草稿不意外丢失，无明显截断|普通iPhone截图/操作|
|真实HealthKit|权限、撤回、实际样本与真机生命周期单独记录|实体设备另验|
|Duo姿态|仅实际Duo开合和像素证据可宣布通过|独立硬件/姿态证据|

已有完整Gate成绩属于它们的准确源码。新版本须重新核受影响路径。一次完整Gate通过不等于所有行都已验收，也不等于真实医疗效果。

## 演示数据与失败准备

准备一组无隐私的正常案例和一组数据不足案例，记录固定时区、日期窗和来源。正常案例应在实际界面够清楚，不堆十几种药和几十张图。故障案例证明诚实降级，不必占用很长演讲时间。

保存最后可运行版本、原始截图、准确联调结果和标注清楚的备用录屏。现场网络不可靠时，可选择明确展示已录制的在线环节，再实时操作本机预览；不能播放录屏却暗示当场实时联网。

## 项目负责人亲自验收

最终必须能独立完成：启动正确版本，说明每项数据从哪里来，走完核心演示，展示一条来源，取消一次任务，解释网络失败时怎么办，指出仍未验证的能力。讲演稿不应比实际产品更完整。
