# 本地接力与并行分工

## 使用前提

这是待项目负责人确认后使用的接力提示，不是自动开工指令。当前阶段只读评估和文档记录。确认后建议两个主线程，加按需只读审查子代理；不建议三个主线程各自重建一个完整App。

一个总包足够：先读产品方案与技术方案，再把下面A、B提示分别交给两个线程。原候选包只用于恢复和比较，禁止互相覆盖解压到已有工作目录。

## 开始时共同完成的零阶段

两条线程先报告准确HEAD、工作树状态、worktree列表、已有构建进程、可用磁盘和当前Device Hub设备。保留未提交修改与删除，禁止自动reset、clean或恢复它人删除的文件。确认唯一集成负责人、一个目标基线和文件归属表。

必须区分根现场、健康/PDF组合和阅读候选。先核现有本地工作树是否已包含成果；不因GitHub某个候选对象不能解析就重写实现，也不无审查地应用整份patch。缺源时使用原包校验后恢复到独立位置。

零阶段的交付是一页状态清单：当前能运行什么；已有健康资料与AI各走哪条链；哪个文件由谁改；哪些内容暂不碰。该清单和用户确认的范围是后续工作的共同依据。

## 线程A 统一基线与复诊任务

建议提示词：

你负责MedCue本轮唯一集成基线，以及“准备复诊资料”的事实和任务链路。先只读核当前根目录、健康/PDF候选5ef00ce与阅读候选4e22a1，不覆盖既有修改。采用最小、可回滚的整合方式，记录准确依赖及来源，不把不同版本的测试成绩相加。

复用VisitSummaryDataPipeline、HealthEvidence、已有PDF payload和预览分享。新增的任务桥只负责捕获同一份事实、组织草稿、管理状态与失效。药品、计划、历史记录和健康档案不能因此再复制一套数据库。先完成不依赖网络的合成主路径，再按已确认范围联调在线AI。

核实健康数据的客户端guard、模式要求、上下文附加与错误展示。不要把问题误归为豆包拒答。改进是对本次许可和摘要范围作有针对性的支持，不是无条件删除所有检查。真实上游型号从非秘密配置标识核对；不得显示密钥。演示使用固定无隐私合成数据，真实数据和新凭据动作另行取得必要许可。

你拥有共享核心模型、任务编排、AI请求/错误路由、导出适配、工程配置、集成提交和重构建调度。先向线程B提供稳定的只读快照/草稿接口和mock样例。B需要修改共享文件时，先由你整合；双方不得同时写同一文件。

每个小提交说明变更、准确测试、未运行项和回滚点。发现数据不一致、未知owner、错误覆盖或敏感资料越界时停止依赖步骤。不要合并远端PR或发布版本，不扩大为家庭/医生平台。

## 线程B 首页任务入口与演示验收

建议提示词：

你负责基于线程A稳定接口的复诊任务界面、个人状况首页的最小调整，以及演示/可用性验收。先阅读本轮产品方案和已有UI，避免复制Google/Apple视觉资产，也不要从零重做所有Tab。

优先保持今日用药操作清楚可达；加入适量近期回顾与“准备复诊资料”入口。草稿把事实、用户补充、待问医生问题分开，来源可展开，允许删选，显示真实进度/失败。旧数据或网络失败有诚实可用的本地结果，不伪装AI成功。

你只修改分配给你的新任务View、展示适配、独立fixture/UI测试和演示文稿。不要修改共享模型、AI factory、PBX、App入口或既有PDF服务；需要这些变更时发给线程A。UI只能依赖双方确认的接口。使用合成数据，不申请真实患者资料。

完成后提供普通iPhone实际截图、操作步骤、大字体与返回/取消/重复操作结果。记录准确源码和设备/runtime。只在你认领的设备工作；重构建与线程A错峰。Duo特有姿态未经实际验证不得写通过。

## 工作顺序与时间预算

以下是阶段目标，不是保证完成时刻。以10月17日晚形成可演示冻结版作为10月18日前目标；赛事具体时间仍待负责人确认。

- 阶段0，约前2小时：只读对账、恢复源核验、唯一基线、分工表、固定演示案例。失败则不启动两路写入。
- 阶段1，约接下来4至6小时：A统一已有成果并固定事实/草稿接口；B用mock梳理入口与预览，不动共享文件。
- 阶段2，约接下来6至10小时：A完成任务桥和在线合成契约；B完成真实UI连接。必须先有接口约定再并行。
- 阶段3，第二天前半：一次准确集成版本的原生聚焦测试与演示操作。先诊断失败，不盲重跑完整Gate。
- 阶段4，第二天后半：只修阻断演示与事实正确性的缺陷，保存证据、脚本和回退版本；负责人亲自走一遍。

如果时间不足，先取消首页大改、事件锚定比较与额外装饰，保留复诊准备主路径。若在线AI未验证，不能把这项高光宣布完成；可如实展示本机资料整理，列出AI缺口。不要用低价值新功能填补失败。

## 低负载与磁盘规则

- 两个线程不等于同时跑两个重构建。最多一个xcodebuild/完整Gate进程，明确认领和释放。
- 优先复用已有编译缓存与现有runtime，不下载新工具链、不全局切换默认、不执行clean build作为习惯动作。
- 默认同一时间只启动一个模拟器。只有现有机器余量和实际任务需要允许时，才使用第二个已有设备；每个设备明确owner，禁止同时操作同一UDID。
- 使用Device Hub，不恢复暂停的iPad lane。不能因为父线程缺GUI工具就伪造UI验证。
- 原件、旧xcresult与关键截图保留。不要自动删除缓存或旧证据腾空间；如空间不足，先列明占用与可回收项，按已有授权处理。
- 复用worktree或建立必要的最少独立工作树，避免每个子代理复制整仓库、重复下载依赖和同时启动服务器。
- 在交接记录写明构建/设备owner、当前进程、失败原因、下一步。若进程不存在才重新认领，不凭聊天时间推测已释放。

## 集成控制

设置一个集成负责人，所有共享文件由其单写。使用一个简洁的协调文件记录OWNER、允许修改路径、接口版本、当前阻塞和构建占用。子代理默认只读审查，实施子代理必须有独立文件范围。

Git和Gate能检测一部分问题，不能消除语义冲突。例如两条线程分别修改同一个事实模型，即使Git能自动合并，也可能使PDF与AI解释不一致。因此共享契约先确定，再分工。

各阶段保留小提交与可运行回退点。完整Gate只在准确集成HEAD上解释，不把旧HEAD成功覆盖新改动。草稿PR不等于合并批准，演示准备不等于发布授权。
