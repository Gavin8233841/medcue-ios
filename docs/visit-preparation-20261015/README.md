# MedCue 产品收敛与复诊准备方案

更新日期：2026年10月15日。目标窗口：10月18日前。本文是评估与接力方案，不表示以下新增流程已经实现，也不授权自动合并、发布或处理真实患者数据。

## 先读这五句话

1. MedCue 的建议定位是面向长期用药者的个人用药与健康助手。日常管理是基础，复诊准备是集中展示价值的场景。
2. Apple 健康通过 HealthKit 提供经授权的数据来源。MedCue 应围绕具体用药任务补充它，而不是再造一个通用健康平台。
3. 健康回顾与复诊 PDF 已有独立原生验证成果；阅读体验候选也有自己的验证。当前首要问题是统一版本，而不是从零重做。
4. 健康档案与复诊资料应共用事实层：资料入口随刷新展示现有事实，复诊资料是按本次范围、由用户选取的快照。
5. 两天目标是一个可控、可解释、能真实演示的端到端流程。家属云同步、医生小程序、新服务器及复杂特效暂不进入这一目标。

## 状态口径

“已有实现”指源码存在；“已验证”必须说明准确版本及验证类型；“待集成”指不同候选尚未在同一版本完成验证；“建议”是本轮提出的设计。合成测试、模拟器截图、真实健康数据验收与真实用户反馈分别记录，不能互相替代。

本文不把“国内首创”“全球唯一”“改善疗效”“验证了真实吞服”作为现有结论。产品差异化应通过具体任务对比和可复现演示证明。

## 立即执行的前提

实施前由项目负责人确认本轮范围和唯一集成基线。先按 HANDOFF 的只读检查建立版本清单，保护已有未提交修改，随后才分配写入任务。旧的冻结文件规则不得因为本文出现新建议而自动解除。
