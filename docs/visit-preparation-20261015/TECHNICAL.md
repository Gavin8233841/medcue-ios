# 技术路线与现状核对

## 唯一目标

在统一的可运行版本中，完成“选择资料范围 → 读取用药与健康事实 → AI整理复诊草稿 → 用户删选 → 预览并导出”的任务。复用既有统计与PDF实现，不再造第二套数字。第一轮只规划与纯合成可行性检查；本文件不表示该任务已连通。

## 已有能力可复用

用药模块已经有药品、计划、任务、操作记录、记录更正/重开、库存盘点与估算、提醒提交后调度等确定性实现。AI的普通上下文可包括经许可的药品、计划、记录、风险与说明书，不是完全脱离App的聊天框。

复诊流水线已经读取方案变更历史，并构建范围化快照和导出值对象。健康组合已有新的HealthEvidence事实，不能因为普通AI上下文没有某字段，就误以为整个App没有这份数据。

主要复用位置（以实施时准确组合源码核对）：

- `Services/VisitSummaryDataPipeline.swift`：资料捕获、剂量变更、计划与导出值对象。
- `Services/VisitSummarySnapshotRevision.swift`：资料变动判据。
- `Views/VisitSummaryView.swift`、`VisitSummaryPDFExportViews.swift`：现有范围选择、PDF预览与系统分享。
- `Services/HealthKitService.swift`、Core的`HealthEvidence.swift`：健康来源、窗口、覆盖与失效。
- `Services/MedicalAIContextBuilder.swift`、`MedicalAIClientFactory`、Core的提示构建：已有许可与在线/本机路由。

普通文字导出和PDF的字段目前不完全相同。新任务必须用统一的选择与事实适配两种输出，不能假定它们已经天然一致。

## 健康数据为什么没有进入在线AI

已核到的限制是项目自己设置的客户端策略，不是已证明豆包拒答。健康证据基础实现的在线factory包装器会在请求带健康证据时、调用网络transport之前拒绝；正常附证据还受本地模式与独立许可条件约束。本机健康问题可走确定性摘要，所以“界面给了健康回答”也不能反推在线模型已经收到健康事实。

仓库Broker实现使用火山Ark上游，部署实际模型待核，模型选择来自服务端配置。UI默认值、测试里的模型名不能证明线上部署就是某个豆包型号。本轮未读取密钥或线上配置值。当前错误呈现有可能把本机政策和网络错误都归成笼统的没有结果，实施时应给出正确原因。

该限制来自当时未完成的健康云传设计，不是不可改变的技术障碍。为了演示，可以优先让无隐私的合成健康摘要经过真实的候选链路；真实健康摘要则由用户明确选择本次资料与接收服务，不能把过去的本机许可自动升级为云传许可。

## 最小任务架构

不要从一个开放式Agent平台起步。采用有限步骤的任务编排器即可：

`选择范围 → 捕获事实 → 整理草稿 → 用户预览 → 导出完成`

失败、取消、数据更新各有明确状态。自由聊天不能绕过这个任务直接修改药品或计划。

### 同一份事实

建议新增轻量的复诊任务快照与草稿适配层，复用现有模型，不迁移整库。快照包含任务ID、范围、报告时区、来源版本、所选药品与健康事实、覆盖与缺失说明。每条事实有稳定的本次引用ID。草稿只是引用事实并加说明，不再自行计算计数或生成新的健康读数。

资料变化后，旧草稿提示需刷新；取消只取消本次任务，不更改原药品与记录。导出取用户确认的同一事实集合，预览和PDF的数字、单位、日期窗、来源应一致。

### 模型负责什么

模型可以整理用户关心的问题、把允许的事实写成易懂的文字，并提出有限的澄清。它不负责重算数值、补齐缺测、判定真实吞服或推导药物因果。模型输出用结构化草稿形式返回，并引用本次事实ID；来源不匹配的内容不进入正式事实区。

“我应该问医生什么”与“记录里发生了什么”分开显示。用户可以删选问题，不能让模型编写的新诊断伪装成档案事实。语义检查不足时保留确定性资料，不把任意自由文本当作已核医学结论。

### 在线摘要的竞赛最小范围

先限定单用户、单任务、最少必要摘要。无需为演示新建家庭后台、OAuth平台或长期云端健康档案。保留现有受保护服务与超时、大小限制，明确一次任务的请求与证据版本，晚到结果不得覆盖新选择。

合成案例不含真实隐私，可用于未来获准的真实模型联调；真实数据发送前，清楚展示所选类别、日期范围和接收链路，由用户确认本次发送。可集中在一处完成，不应每个步骤反复弹窗。服务商处理条件尚未知时，不用真实资料试探。

保留既有独立健康许可及快照守门；发送与提交前复核当前许可、本次有效期、资料和接收方。撤回、过期或变更后拒绝旧请求和迟到结果，不自动切换服务商。重新授予许可不能使旧响应恢复有效。

本次不新建或扩大长期凭据，不读写敏感账号设置。若已有服务不可用，先完成本机资料任务；同时明确AI联调未完成。降级可以让演示不中断，但不能把本地模板说成真实模型输出。

## 可行性核对与尚未验证的部分

本轮已执行两项注入mock的实际Broker合成检查，全局网络禁用，均通过。其结果只用于确认当前请求契约与上游配置方式，没有访问真实服务商，也不证明线上模型质量或真实健康数据可传。既有HealthEvidence、快照与PDF测试可作为新增差异测试的基础。

下一轮至少验证：

1. 一份固定合成快照能产生事实列表、草稿和PDF，字段保持一致。
2. 取消、重复点击、换窗、改记录、晚回包不会产生错误保存或旧资料回流。
3. 无数据、稀疏数据、查询失败、重复来源、单位/时区边界都有可理解结果。
4. 真实候选模型至少完成一次无隐私合成资料联调；否则不得声称在线AI路径通过。
5. 正常iPhone上的入口、预览、返回、草稿连续性和大字体确实可操作。

两天内不追求把所有历史技术债清零。若无法统一基线或事实与PDF不一致，停止增加新功能；先修主路径。Duo开合和真实HealthKit数据验收继续单列，不影响如实展示普通iPhone上已通过的合成流程。
