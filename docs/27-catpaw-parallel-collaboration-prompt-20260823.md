CatPaw 有能力独立读写代码、运行测试、操作 git 分支，但它**不了解本仓库历史、不认识产品 owner 的隐含偏好**。因此分配时遵守：

1. **你（Codex）保留主干**：`AIAssistantView` 的编排重构（#10）、同意事务（#12）、`project.pbxproj` 变更、任何涉及医疗安全文案/边界的最终判断，默认归你。
2. **CatPaw 接边界清晰的增量**：新增文件为主、改动面可枚举、验收标准客观的任务。
3. **尊重阻塞链**：#6/#9/#10/#11 实现被 #1（仓库历史规范化）阻塞；阻塞期间只分配"发现、规格、测试先行、独立原型"类任务，实现必须从规范化后的 `main` 起点开始。
