# MedCue Issue #161：Duo 核心体验与现场演示规格

日期：2026-10-09。状态：可实施设计方案，尚未完成 Duo SDK 编译、设备验证或用户测试。

## 当前可落地的一条故事

**拿起时看清一味药，展开时同时核对身份与计划。**

首轮只改未冻结的 `MedicationDetailView.swift`，把当前真实药品的身份、规格、疗程和提醒按可用空间重排。宽屏首屏不再只是一张大图；窄屏与大字体保持完整文字。演示用现有路由打开真实详情，数据仍来自同一药品 Store。

`AppRootView`（#113）与 `MedicationsView`（#73）冻结，因此列表 + 详情双列仅为以后整合目标，不是本轮完成项。禁止绕开根导航另做一套独立假 UI，或把未接入的演示页宣称为 App 适配。

范围是同一药品详情的可读性与空间利用。不新增医疗建议、服药自动确认、AI 总结、健康数据关联、家属面板或半折专属功能。

## 首轮实施规格：现有详情的响应式重排

```text
窄 / 大字体：同一滚动页面            宽：同一滚动页面（不是新导航）
┌───────────────────────┐       ┌────────────────────────────────────┐
│ 药盒照片              │       │ 药盒照片  │ 药名、规格、编号       │
│ 药名、规格、编号      │       │           │ 现有照片操作          │
│ 照片操作可换行        │       ├─────────────────┬──────────────────┤
├───────────────────────┤       │ 药品信息        │ 疗程与提醒       │
│ 药品信息              │       │ 通用名、规格    │ 剂量、时间       │
├───────────────────────┤       │ 剂型、来源      │ 疗程、时区       │
│ 疗程与提醒            │       │ 备注            │ 现有修改入口     │
├───────────────────────┤       ├─────────────────┴──────────────────┤
│ 剂量变化 → 库存       │       │ 剂量变化 → 库存 → 近期记录         │
│ → 近期记录 → 其余区  │       │ → 其余原有分区                     │
└───────────────────────┘       └────────────────────────────────────┘
```

- 保留一个 `List` 或等价的单一滚动容器；只提取当前详情文件内部的 photo/identity、medication info、plan 内容构建器，状态和 sheet modifier 保留在页面根部。
- regular 下才考虑横排，仍必须让内容自然放得下；compact、accessibility Dynamic Type 和不足以容纳完整标签/值的空间回到竖排。不以设备型号、英寸或一个硬编码屏宽决定。
- 第一组是现有照片 + 身份，横向时图片保持原比例且不过度放大，文本获得伸展空间；竖向时沿用原次序。照片按钮自然换行或竖排，不让三个 small 按钮挤成细小触控区。
- 第二组才是“药品信息 / 疗程与提醒”，建议内部独立子组、同顶对齐、细分隔，无卡片套卡片。窄屏阅读顺序仍是药品信息后计划。所有原值、空态、备注、时区、修改入口必须保留。
- 多个计划完整保留，长内容可使横排回落竖排，不截成一条“下次服药”摘要。没有计划时呈现真实空态及原“建立疗程与提醒”入口，不制造假数据。
- 保留之后的剂量变化、库存、近期记录、说明书、风险和高级操作原顺序。近期记录每行在大字体改为可换行结构，状态文字不能挤掉剂量与时间。
- `SharedViews`、根导航、列表文件不动；确需改通用 InfoRow 时先在详情内部做局部可读行，不扩散到冻结范围。没有必要引入新依赖或设计平台。
- 首轮不手工分配折区，不自造铰链参数。对折区/系统栏的原生适配是否合格单列验收；普通网页宽窄切换只能验证重排视觉。

## 三种状态必须分别汇报

1. **云端视觉候选**：尺寸/字体场景与布局规则已写出或预览，可供实现比较；不代表 SwiftUI 编译或功能完成。
2. **主流程接入**：真实详情文件有变更，现有 route 打开、真实模型绑定、原编辑弹层与数据路径保留，通过可运行的原生构建/测试后才能称已接入且可运行。只有代码静态检查时明确说“候选补丁，原生运行待验”。
3. **Duo 原生验收**：在对应官方 SDK/runtime/设备核查外内屏、折区、系统栏、开合与大字体，留下 commit + runtime + 连续录屏。未做到不能说 Duo 适配完成。

## 证据与设计取舍

- Apple Duo 设计视频明确推荐 compact / regular size class、safe area 与系统导航；展开可用 split view 保持同一层级；外屏和多数内屏姿态的栏位由系统移动。不要按设备尺寸设置固定断点，不手绘右侧栏，不以屏幕物理英寸决定布局。[官方视频，3:42、5:07、7:34](https://developer.apple.com/videos/play/tech-talks/111466/)
- Apple 的 Reminders 示例展示双列随折叠调整；连续滚动内容无需整体挪出折区；优先让系统处理弹层和导航避让。此项目先用标准容器，定制 reserved region/arrangement 仅在实际遮挡证据出现后考虑。[官方自适应视频](https://developer.apple.com/videos/play/tech-talks/111463/)
- Apple Health 的药品管理以药品身份、计划、记录为核心，详情支持回看历史。借鉴清晰的信息职责，不复制图像或界面。[Health 官方使用指南](https://support.apple.com/en-au/guide/iphone/iph811670c81/ios)
- Things 的 OS 26 官方展示保留熟悉结构，以间距、圆角和少量侧栏材质更新视觉。借鉴克制的密度与分层，不引入其资产，也不声称它已适配 Duo。[Things 官方实作](https://culturedcode.com/things/blog/2025/09/things-for-os-26/)
- HIG 页面和 prepare 根 URL 在本次文本读取中未返回可读正文；以上设计以可读的 Apple 官方视频全文为依据。SDK 参数、设备逻辑尺寸、准确 API 可用性由技术核验文件负责，不在此猜测。7.6/5.4 英寸及 iOS 27.1 是本次任务输入，不换算为布局像素。

## 后续整合目标：列表 + 详情（等待冻结解除）

```text
紧凑：列表 → 药品详情                    展开：系统双列导航容器
┌───────────────────────┐           ┌──────────────────┬──────────────────────────┐
│ 药品 / 分组 / 当前筛选 │           │ 药品 / 当前筛选  │ 所选药品                  │
│ 药品 A                │           │ 药品 A           │ 图片  药名、规格、编号    │
│ 药品 B [已选择]       │   展开    │ 药品 B [已选择] │                          │
│ 药品 C                │ ───────→  │ 药品 C           │ 当前计划与提醒            │
└───────────────────────┘           │                  │ 近期记录                  │
             ↓                     │ 原有概览入口     │ 库存 / 更多既有详情       │
┌───────────────────────┐           │                  │                          │
│ 返回药品 / 药品 B     │ ←─ 合上 ─ └──────────────────┴──────────────────────────┘
│ 身份 → 计划 → 记录    │              系统安全区、工具栏和标签栏由容器负责
│ 其余详情可滚动        │              示意图不代表物理屏幕比例或栏位坐标
└───────────────────────┘
```

- compact：保留已有列表→详情 push 语义。标题、药名、剂量/规格优先，完整名称允许换行。禁止为了塞首屏缩小文字。
- regular：两层层级并列，列表与详情各自滚动。只有两列，不再叠加第三个自绘 tab sidebar。未选药时右侧为“选择药品，查看计划与记录”，不替用户自动挑药。
- 展开时已选药品显示在详情，列表高亮相同 ID；切换药品仅替换详情。药品概览入口可保留，不能为展示偷偷删除原功能。
- 此方案需根导航与列表解冻后整合。首轮详情重排不实施这里的双列导航，也不为镜头调整临床信息内容。
- 不以固定宽度或屏宽比编码列分配；采用系统 split view 的布局策略。分屏、旋转、系统遮挡及极大字体需要时收为单列。

## 视觉规格（应用设计目标，不是 Apple 设备参数）

- 底色与内容面：systemGroupedBackground / secondarySystemGroupedBackground；主次文字用 semantic primary / secondary，黑白模式均可适配。
- 蓝色只用于当前选择和操作；现有药品色保留身份意义。状态同时有文字/图标，不能只靠绿橙区分。
- 沿用系统字体：页面 largeTitle、详情药名 title2 semibold、列表药名 headline、正文 body、补充说明 subheadline。药名/规格/计划不降到 caption。
- 自定义内容内边距建议 16pt，块间距 16–24pt，相关行间距 8–12pt；系统 List 使用原生 margin，不叠加第二套不一致边距。
- 图片沿用现有 64pt 缩略图，不把药盒图片扩成空泛大封面；详情图片维持原比例，缺图使用现有符号。展开增加同时可见的信息，不把每张卡放大。
- 选中行使用轻微蓝底与清晰选中语义，不增加发光、厚描边、悬浮阴影。正文实色底；玻璃质感留给系统导航。
- 可点目标至少 44×44pt；关键操作项目目标 48pt 以上。以上是本项目触控规格，不用小字号挤出空间。

## 适老与大字体

- 接受系统 Dynamic Type，accessibility sizes 保守降为单列；普通大字也以实际内容能否排下为准，列表行可增高。
- 把旧行内三指标从横排改为可换行/竖排仅作为后续独立组件修复，不在冻结文件直接重写；药名、规格、时间与单位不得截断或 minimumScaleFactor 压缩。
- VoiceOver：一行可读“药名，规格，下次时间，状态”；选中行包含 selected trait。打开详情后焦点落在药名；开合不能自动跳到页首或另一个药品。
- 验证正文对比度至少 4.5:1；增加对比度、降低透明度后仍有选择态。Reduce Motion 开启时不用自绘大位移动画。
- 依据：[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[UI Design Tips](https://developer.apple.com/design/tips/)、[Accessibility testing](https://developer.apple.com/documentation/accessibility/performing-accessibility-testing-for-your-app)。

## 后续跨布局连续性验收契约

适配只改变呈现。单一状态拥有者管理 activeTab、生命周期筛选、selectedMedicationID、navigation path、编辑草稿与弹层。不得因换布局重复注册提醒、写服药记录、重建 Store、再次弹权限。

- 外屏列表选择 B → 详情 → 展开：B 保持，筛选不变，详情不白屏，列表选择可见。
- 展开选 C → 合上：显示 C 的详情，返回行为仍正确；反复开合不产生重复 path。
- 半折与相机/Live Activity 占位：交互没有落在受限区下；系统弹层可操作。必须使用官方 runtime 验证，普通浏览器 resize 不等价。
- 分屏窄窗口 / 大字体 / 旋转：允许单列，内容和动作仍可达，没有横向截断。
- 编辑未保存时开合：输入仍在，保存只一次。若该路径尚未实现，首轮演示明确仅覆盖只读浏览，不宣称草稿连续性。
- 若开合跨 scene，状态连续性需技术实现和实测，不能只靠分支里的 @State 推断通过。

## 60 秒决赛现场演示

0–15 秒：从既有药品流程打开“演示药品 B”详情，窄布局看药名、规格与当前计划。使用合成数据，注明“演示数据”。

15–35 秒：展开，照片与身份并列，药品信息和疗程提醒同时可见。旁白：“展开后，同一味药的身份和当前计划可以并排核对，文字保持正常大小。”在官方 runtime 验证前只展示窗口重排，并明确称为布局候选。

35–50 秒：大字体切换为顺序单列，完整药名、剂量、单位、时间保留。旁白：“字体放大时优先保证读得全，不为了双栏压缩文字。”

50–60 秒：返回常规字号或合上（仅原生已验证后），继续原详情。结尾区分已经证明的重排/可读性与仍待验证的设备能力。

列表 + 详情整合后可追加选 B → 展开选 C → 合上仍 C 的连续录屏；在冻结解除前不以此作为本轮演示承诺。未验证编辑草稿跨开合连续性时不演示、不宣称。

## 可以讲的收益与停止线

本轮可以讲：展开同时呈现药品身份与计划；同一真实详情适应宽窄；大字体完整可读；原有编辑与记录入口保留。只有实际测量前后首屏可见内容后才说“减少了多少滚动”。

后续列表 + 详情整合并实测后可讲：换药少一次返回、同一选择和筛选连续。

不能讲：提升依从性某个百分点、降低漏服/误服、临床有效性、所有姿态完美支持、真实患者受益，除非另有研究与测量。

完成标准：真实详情一处可运行的宽窄重排 + 两种字号可读 + 现有操作无回归 + 已知设备限制诚实记录。美化止于对齐、密度、颜色、可读性，不另建仪表盘。
