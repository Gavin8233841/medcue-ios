# MedCue iPhone Duo 适配计划

Issue: https://github.com/Gavin8233841/medcue-ios/issues/161

建立：2026-10-09。起点：`4d9c6d50d46a5735dc014da5434e1063d8cf7493`。

## 目标与产品价值

在决赛答辩中展示一个真实、有美感、能解释用途的自适应体验：窄窗口随身查看一味药；宽窗口边选药边核对计划与记录；窗口变窄仍保留同一药品和操作进度。适配积极性由可验证的行为与证据体现，不靠设备标志或放大界面。

持续在云端研究、实现、审查及优化，减少用户接手。先利用现有资源，不为微小视觉差异无限返工。不得为展示效果牺牲服药记录一致性、可访问性、隐私或普通 iPhone 体验。

## 已核实与证据边界

- Apple 官方产品及开发入口存在：<https://www.apple.com/newsroom/2026/09/apple-unveils-iphone-duo/>、<https://developer.apple.com/iphone-duo/>。
- SDK/工具要求以当日官方准备指南为准：<https://developer.apple.com/iphone-duo/prepare/>。不猜测 point 尺寸、倍率或姿态自动化命令。
- 当前仓库最低 iOS 17.0，target family 为 iPhone+iPad；iPhone 仅竖屏，iPad 支持四方向。因此给 iPhone 测试设置 orientation 不自动证明窗口变化。
- 扫描框与识别区域存在静态计算分歧；这是源码事实，尚非真实相机漏扫的复现结论。
- 尚无本 Issue 的原生构建、Duo 模拟器、真实设备或可用性测量通过证据。

## 范围与非目标

覆盖容器布局、安全区、关键文字与按钮、键盘和 sheet、导航/选中状态、草稿、服药确认、无障碍与适老模式。分析既有 Live Activity、通知、PDF、Health 和 Watch 的影响并按实际边界回归。

不新增医疗判断、剂量建议、第二套药物模型、多窗口写入架构或外屏健康内容镜像。不为本次适配购买设备、付费、创建凭据、改变授权和安全设置或发布版本。云端截图/网页原型只证明设计或相应实现，不代替 SwiftUI 与真实 Duo 验收。

## 文件所有权及执行约束

### P1：扫描几何真实问题修正

目标：视觉框与 AVFoundation 识别区域使用同一实际容器几何，缩放/安全区变化后及时更新。

范围：现有 `ios-app/MedicationAdherenceApp/MedicationAdherenceApp/Views/BarcodeScannerView.swift` 与新增独立几何测试；不改变相机权限、会话启停、识别类型、回调幂等或导入确认。

验收：矩形有限非负、在容器范围内；狭窄/短窗口可用；同一次布局采用同一矩形并正确变换到 preview layer；resize 不残留旧ROI。分别验证SwiftUI局部坐标、preview layer坐标和归一化ROI，覆盖aspect-fill裁剪、原点偏移与layout更新顺序；零面积/尚未布局时必须保守延后有效ROI或阻止识别，不能退化成意外全画面扫描。纯几何测试不证明AVFoundation实际转换。正常尺寸保持现有视觉语言，文本不能靠遮挡取空间。

### P2：状态连续性与主展示场景

先新增独立窗口变化测试，复用现有合成fixture与持久化检查接口，不另建模拟业务系统。先验证支持旋转的iPad路径，明确不能替代Duo。

并行设计列表+详情布局。选中药品、导航、草稿和操作身份必须独立于布局分支；不得依赖重复出现/消失事件写业务。大字体或空间不足可恢复单列；保留明确主要动作、可读剂量和状态。

根导航重叠协调前，允许独立展示组件与隔离原型，不强行插入冻结文件，也不把原型称已接入产品。

进度分为三个独立状态：①云端候选完成（代码/几何或设计验证）；②主流程已接入（真实路由、数据与交互接通且相关原生测试通过）；③Duo原生验收通过（准确SDK/runtime转换与设备边界证据）。第一状态不能自动升级为第二或第三。冻结解除前，先在未冻结的 MedicationDetailView / MedicationOverviewDetailViews 等展示路径内落实可回滚的宽窄排版；根级列表+详情组合保留为待协调里程碑。

### P3：回归与展示质量

按下面矩阵覆盖核心任务与高风险转换。优先解决可达性、错药/重复动作、草稿丢失和明显视觉问题，再处理装饰。

视觉交付固定同一组合成数据的紧凑、展开、大字体画面及短演示脚本：主动作可达、药名与剂量完整、层级/留白一致、状态不只靠颜色。比较完成同一任务需要的返回或切换次数，描述可观察差异，不编造效率百分比、疗效或依从性改善。P1扫描修正是可靠性成果，不单独充当完整展示出口。

状态测试明确同一medication ID与计划事件ID，按业务事件断言记录数而非按药品粗计；取消、失败和重复回调不能导致成功记录。无需姿态噱头或所有页面双栏。

### P4：成果与审查

独立审查累计差异；每个提交重新核对适用测试与证据。Draft PR记录准确SHA、运行环境、通过/失败/未运行和外部验证缺口。证据标为设计预览、确定性测试、原生模拟器或真实硬件，禁止互相替代。未获完整证据不称完成适配，不合并或发布。

## 最小风险驱动测试矩阵

| 维度 | 必查 | 证据 |
| --- | --- | --- |
| 几何 | compact/regular、窄宽短高、安全区不对称、键盘 | 几何测试+实际UI截图；不编造设备point尺寸 |
| 核心任务 | 药品列表/详情、确认/取消服药、编辑草稿、错误态 | 任务身份与持久化记录，不只检查按钮存在 |
| 转换 | 开合、旋转、分屏、后台/恢复、通知入口 | 实际支持工具操作记录与前后状态 |
| 一致性 | 取消=零写入、成功=恰一次、失败不成功、重复事件不重复副作用 | 既有合成fixture与存储检查 |
| 无障碍 | AX大字体、VoiceOver焦点/顺序、减弱动态、对比度 | 自动审计与人工/设备证据分别列明 |
| 视觉 | 中英长文、空态/加载/失败、操作层次、整齐留白 | 实际画面审查，演示用合成数据 |
| 系统入口 | 现有Live Activity、通知、Watch、PDF、Health | 根据改动边界选择回归；无改动N/A需依据 |
| 平台 | 当前最低系统、普通iPhone、支持的iPad、Duo runtime | exact SHA+SDK+runtime；模拟器不冒充真机 |

research.md 的广泛矩阵是风险库；本计划按切片影响选择的矩阵才是实施验收。双窗口仅在现有产品本来支持时回归，不为满足研究清单新增架构。矩阵按风险选代表组合，避免盲目做全部笛卡尔积。相机、触感、真实Watch通信和硬件表现保留真实设备验收边界。

## 停止、回滚与持续推进

冻结文件交叉、未知API、安全/隐私/费用/凭据需求只阻塞相关分支，继续独立云端工作。无可证明收益的设计方案否决并记录，避免堆功能。回滚以独立提交为单位；原始证据只追加说明，不改写历史。

停止当前实现切片的条件：接受标准已满足并完成独立审查，或进一步推进需要不可用原生环境/明确新授权/未解决所有权。继续主目标的其他可行切片；不以任意两天预算代替当前重型任务目标，也不把无休止微调当完成度。
