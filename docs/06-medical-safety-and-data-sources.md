# 医疗安全边界与数据源

## 安全红线

Apple App Review Guidelines 1.4.1 对可能用于诊断或治疗的医疗 App 会更严格审核，并要求 App 提醒用户在作出医疗决定前咨询医生。1.4.2 还规定药品剂量计算器必须来自药品制造商、医院、大学、医保机构、药房或其他获批实体，或取得 FDA 等监管机构批准。

因此本项目不做剂量计算器，不自动决定用药方案，不给个体化治疗建议。

## 产品表达边界

允许表达：

- 用药提醒。
- 用户自主管理服药记录。
- 将说明书原文转成更易读的摘要。
- 展示说明书中明确写出的禁忌、警示、相互作用或不良反应。
- 提醒用户向医生或药师确认。

禁止表达：

- App 已确认某药适合用户。
- App 可判断某症状由某药导致。
- App 可自动调整剂量、频次或疗程。
- App 可替代处方或医嘱。
- App 可判断药品真伪或医保销售信息。

## Apple Health 与 HealthKit

Apple WWDC25 介绍了 HealthKit Medications API，可读取用户授权的 medications 和 dose events。其对象包括 HKUserAnnotatedMedication 和 HKMedicationDoseEvent；用户可按药品授权，授权某药后可读取相应 dose events。

落地策略：

- 初赛文档可写“计划接入 Apple 健康/HealthKit”。
- 第一版开发先做本地用药记录和本地提醒。
- 等 Xcode 项目和可用 SDK 确认后，再判断 HealthKit medications API 是否进入复赛版本。
- HealthKit 数据只在用户明确授权后读取，不用于广告、营销或无关数据挖掘。

## 药品数据源

### openFDA Drug Label API

openFDA Drug Label API 提供 FDA 药品标签数据，覆盖处方药和非处方药，字段可包含用法、警示、不良反应、相互作用等。官方也提醒不要依赖 openFDA 作医疗照护决定。

适合作为演示数据源：

- 英文非处方药。
- 说明书可读化。
- 风险关键词抽取。
- 数据来源和更新时间说明。

限制：

- 美国药品体系，不等同于中国上市药品说明书。
- 标签内容结构差异大，不能保证每个字段都有值。

### RxNorm

RxNorm 提供标准化药品名称和编码，可通过 REST API 访问。它适合做药品名标准化、HealthKit medication coding 关联和跨数据源匹配。

适合作为演示数据源：

- 英文药品名搜索。
- RxNorm 编码展示。
- 与 HealthKit medication coding 对接。

限制：

- 不是中国药品说明书数据库。
- 部分完整数据下载需要 UMLS 账号或遵守许可。

### RxClass

RxClass API 可查询药物类别和类别成员，无需单独许可但受服务条款约束。它适合做药品类别解释，不适合作为单独的相互作用判断依据。

### 国家医保药品耗材追溯信息查询

国家医保服务平台 App 提供“医保药品耗材追溯信息查询”，药品追溯码具有唯一性，可查询药品销售信息。国家医保局也明确说明，其他软件或 App 扫描药品追溯码得到的信息不是医保销售结算信息，不适用其结论。

落地策略：

- 本项目不声称通过扫码判断药品来源合法或真伪。
- 扫码能力只用于辅助录入药品包装信息。
- 若用户需要医保追溯信息，引导其使用国家医保服务平台。

## AI 能力边界

允许：

- 对用户提供的说明书文本做结构化整理。
- 对权威来源原文做通俗解释。
- 生成“请向医生或药师确认”的问题清单。

禁止：

- 医疗诊断。
- 个体化处方建议。
- 剂量计算。
- 对生命体征异常作药物因果判断。

## 第一版数据策略

- 使用少量演示药品数据，所有条目保留来源链接。
- 用户录入数据默认只保存在本机。
- 外部 API 默认只查询药品公开信息，不上传用户身份、病史、服药记录或健康数据。
- 如后续需要云同步，必须单独设计加密、授权、导出和删除机制。
