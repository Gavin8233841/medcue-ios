# ADR-0003：iPhone 系统提醒采用固定的隐私保护展示

- 状态：已采纳；代码与系统界面验收仍由 Issue #14 跟踪
- 日期：2026-09-25
- 决策负责人：产品负责人授权本轮由代理决定隐私口径
- 关联：[Issue #14](https://github.com/Gavin8233841/medcue-ios/issues/14)、[Issue #2](https://github.com/Gavin8233841/medcue-ios/issues/2)、[Issue #17](https://github.com/Gavin8233841/medcue-ios/issues/17)

## 背景

通知、AlarmKit、锁屏实时活动和灵动岛会出现在旁观者可见的系统界面。旧实现将药名、剂量和具体完成状态放入这些界面，部分操作还可在没有已验证解锁要求时写入用药记录。iOS 通知预览设置由系统和用户控制，应用不能依靠该设置保护自己提交给系统的内容。

## 决策

受控设备 Beta 对新用户和现有用户采用同一个不可配置的隐私保护模式。本轮不提供详细锁屏内容的选择加入，也不迁移旧偏好。应用提交给 iPhone 系统界面的标题、正文和辅助功能可读文本均不得包含药名、剂量或具体服药、延迟、跳过详情。

| 界面 | 允许展示 | 不展示 | 操作 |
| --- | --- | --- | --- |
| 标准及升级通知 | 通用用药提醒、计划时间 | 药名、剂量、记录详情 | “已服用／稍后／忽略”均要求系统解锁后才送达应用 |
| AlarmKit 标准及升级闹钟 | 通用标题、时间 | 药名、剂量、记录详情 | 停止闹钟不等于记录服药；记录必须在应用内确认 |
| 锁屏实时活动，进行中及结束状态 | 通用状态、时间 | 药名、剂量、具体完成详情 | 仅打开应用，不直接写入用药记录 |
| 灵动岛展开、紧凑、最小化 | 通用提示、符号、时间 | 药名、剂量、具体完成详情 | 仅打开应用，不直接写入用药记录 |
| VoiceOver 等辅助功能输出 | 与同一界面可见内容一致 | 隐藏的药名、剂量、记录详情 | 与可见控件相同 |

Apple 的 [`authenticationRequired` 通知操作选项](https://developer.apple.com/documentation/usernotifications/unnotificationactionoptions/authenticationrequired) 要求设备解锁后才把操作交给应用。现有 Live Activity Intent 与公开 URL 没有同等的已验证解锁和来源证明，因此新的实时活动不提供直接写入控件；旧版 Intent 保留解析兼容但不写入，旧版 URL 不再进入动作事务。应用内确认仍遵守逻辑剂量分组、幂等、显式提交和提交后副作用顺序。#2 在剩余来源授权回归完成前保持开放。

升级后第一次成功读取并进入完整系统提醒同步时，移除旧版待处理及已送达的 MedCue 通知和相关闹钟，再按通用文案重排。读取或清理失败不得宣称迁移完成，并应允许重试。这个一次性替换可能清除仍未确认剂量的旧版已送达提醒；应用内状态保持为事实来源，系统同步失败必须给出可见警告。后续同步继续沿用提醒可靠性策略对有效的已送达提醒的保留规则。Watch 原有隐私模式保持不变。

## 取舍与验证边界

固定通用模式牺牲了在锁屏直接辨认药名和剂量的便利，减少旁观者获得用药信息及旧偏好残留的风险。详细内容选择加入会增加偏好切换后旧通知和活动的清理边界，本轮不采用。对无法证明解锁的实时活动直接操作，本轮选择应用内确认，避免将显示入口误当作写入授权。

源码、模拟器测试和持续集成可验证生成内容、操作选项及迁移逻辑；它们不能证明真实设备在锁定、后台、终止状态和不同通知预览设置下的全部行为。用户授权本轮以 Simulator 代替功能验证，#17 保留独立的真实设备发布矩阵。
