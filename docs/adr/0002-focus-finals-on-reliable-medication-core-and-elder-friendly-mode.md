# ADR-0002: Focus The Finals On A Reliable Medication Core And Elder-Friendly Mode

- Status: Accepted
- Date: 2026-08-22
- Decision owner: MedCue product owner

## Context

MedCue 已经包含用药、趋势、AI、Watch、系统入口和复诊能力，但功能数量没有直接回答“为什么不用普通提醒 App”。复杂入口还可能让长辈更难完成最核心的用药任务。

把产品限定为只服务长辈会丢失通用底座；现在就做远程子女端或医生端，又会在本机价值尚未证实时引入身份、同意、后台和临床边界。

## Decision

1. MedCue 继续面向一般用药人群，尤其是长期、多药、多时段或短期复杂疗程用户。
2. 适老模式成为旗舰差异化体验，但不是唯一产品叙事。
3. 适老模式与普通模式共享药品、计划、任务和动作日志，不建立第二份事实源。
4. 适老模式主要动作是已服用、稍后提醒和需要帮助；无操作保持未确认，不能静默转成主动跳过。
5. 初始家属支持仅限同机协助设置，以及用户配置号码后的显式系统联系动作；不上传通讯录。
6. 远程子女协作和医生小程序留待本机价值、身份、同意与隐私边界证实后再做。
7. AI 只提供有边界的辅助，不成为下载理由或自主用药决策者。
8. 交付以本地小步为主；GitHub 仍负责远程协作、长期 backlog、评审、准确提交 CI 和进入 `main` 的整合。

## Consequences

- 工作优先级由是否减少理解成本、错误风险或证据缺口决定，不由功能数量决定。
- 无障碍、重启、纠错、幂等和诚实动作语义成为产品验收条件。
- 本地小步可归入一个聚焦里程碑分支；进入 `main` 前仍需完整累积 diff、相关 CI 和必要独立复审。
- Xcode、SwiftData、适老模式与真机整合由本机主线负责；YZY 只承担已明确授权且文件不重叠的工作。

## Relationship To ADR-0001

本决策只调整本地小步何时进入 GitHub。ADR-0001 的评审、CI、安全证据、持久决策和 `main` 整合控制继续有效；实际流程以 `docs/DEVELOPMENT_WORKFLOW.md` 为准。

## Rejected Alternatives

- 只做长辈产品：演示更窄，但会排除共享同类用药困难的其他用户。
- 保持宽功能路线：保留已有投入，却不能证明清楚的下载理由和主任务。
- 现在做远程子女端和医生端：潜在价值高，但过早扩大身份、隐私和后台范围。
- 用 AI 或趋势评分领衔：技术可见，却不能证明用户能可靠完成并纠正用药动作。
