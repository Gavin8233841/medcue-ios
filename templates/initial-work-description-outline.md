# 初赛作品说明文档写作骨架

## 1. 问题背景与用户分析（200 字）

写清楚：

- 目标用户：慢病患者、短期用药患者、老年人和照护者。
- 场景问题：漏服、误服、说明书难读、药品难辨识、复诊时缺少真实记录。
- 现有方式不足：纸笔、闹钟和普通备忘录不能同时关联药品、说明、照片、记录和风险提示。
- App 如何降低使用成本：用提醒、照片、记录归档和说明书可读化增强用药纪律。

## 2. 相关竞品分析（200 字）

写清楚：

- 同类工具通常解决什么问题。
- 它们在移动端、交互、易用性或场景贴合上有什么不足。
- 本作品的差异点是什么。
- 与 Apple 健康的关系：不是替代，而是更专注用药依从性，并预留 HealthKit 数据协同。

## 3. 可行性分析（300 字）

写清楚：

- 数据从哪里来。
- 核心功能如何实现。
- iPhone/iPad 上如何运行。
- 初赛到复赛分别完成哪些内容。
- 如何控制开发和演示风险。
- 医疗安全边界：不做诊断、处方、剂量计算或治疗建议。

## 4. App 创新点（300 字）

写清楚：

- 设计理念创新。
- 界面设计创新。
- 交互设计创新。
- 服务方式或场景组织创新。
- 为什么适合 iOS/iPadOS 产品特性。
- 隐私创新：本地优先、最小授权、用户主动分享。

## 5. 应用前景（200 字）

写清楚：

- 用户需求程度。
- 推广场景。
- 社会价值。
- 后续扩展方向。
- 对养老和健康医疗场景的意义：减少漏服误服，保留复诊沟通依据。
